# 负面结果汇总（避免重复走死路）

本文件汇总**已尝试且失败**的优化方向，附实测数据与原因。
**目的：任何后续优化都先查这里，避免重复投入。**

## 平台现状

| 测试点 | 结果 |
| :--- | :--- |
| 1–7 | **Pass（错误 0.00%）** |
| **8** | **Time Limit Exceeded** |
| 9–15 | Skipped（因 8 失败而中断） |

**要过点 8 需约 1.5 倍提速。**

## 已失败的优化（全部有实测数据）

### 1. 向量化（两次，不同设计）

| 设计 | 结果 | 原因 |
| :--- | :--- | :--- |
| tile 逐轮重建 | `large_square` 7.7s → **300s+** | 标量准备开销是标量版的 8.1 倍 |
| x1 载入 UB + `WholeReduceSum` | 中等用例 65ms → **60s+** | 同上 |

**根本原因**：仿真下向量运算**按元素处理**（实测约 5.5 ns/元素），
与标量路径（约 7.1 ns）同量级；而向量化还要额外做布局/广播。

### 2. 内层 4 路手工展开

| 形状 | 基线 | 展开后 |
| :--- | --: | --: |
| 1×512×512×256 | 952 ms | **1029 ms**（更慢） |
| 1×1024×1024×256 | 3584 ms | **3883 ms**（更慢） |

**原因**：编译器本已优化；手工展开增加寄存器压力。

### 3. x1 整行 `DataCopy` 到 UB

| 形状 | 基线 | DataCopy 版 |
| :--- | --: | --: |
| 1×512×512×256 | 952 ms | **23791 ms**（慢 25 倍） |

**原因**：逐行拷贝的调用次数太多（M 次）。
**注**：`DataCopy` 本身在大块时很便宜（32768 元素每次约 0.21 µs），
但逐行拷贝无法摊薄调用开销。

### 4. `LocalTensor::GetPhyAddr()` 裸指针

| 形状 | 基线 | 裸指针版 |
| :--- | --: | --: |
| 1×1024×1024×256 | 3584 ms | **3118 ms（快 13%）** |

**不用**：`LocalTensor::GetPhyAddr()` 是上次平台 Runtime Error 的嫌疑来源
（`GlobalTensor::GetPhyAddr()` 已被平台验证可行——bf16 测试点通过）。
**13% 的收益不值得冒平台崩溃的风险。**

### 5. 关闭 `ASCENDC_DEBUG`（去边界检查）

| 形状 | 基线 | 关闭后 |
| :--- | --: | --: |
| 1×512×512×256 | 952 ms | 992 ms |
| 1×1024×1024×256 | 3584 ms | 3741 ms |

**原因**：`ASCENDC_DEBUG_ASSERT` 的开销可忽略。

### 6. `k` 外层 / `m` 内层（让 x1 值跨列复用）

| 形状 | 基线 | 新结构 |
| :--- | --: | --: |
| 1×512×512×256 | 952 ms | **1244 ms**（更慢） |
| 1×1024×1024×256 | 3584 ms | **4737 ms**（更慢） |

**原因**：需要额外的点积缓冲（`dotBuf` 的读写），净增访存。

### 7. 上界剪枝（Cauchy-Schwarz）

**实测加速比 1.00x**——标准正态数据下上界过松，无法剪掉任何点积。

## 数学上不可行的方向

| 方向 | 为什么不可行 |
| :--- | :--- |
| 减少乘加次数 | `max_n dot(x1_m, x2_n)` 需算出所有点积 |
| 减少访存次数 | 每个 MAC 必须读两个操作数，读次数恒为 `2·M·N·K` |
| 提高算术强度 | x1 需 4MB、UB 仅 192KB，放不下；且每字节输入约对应 1 次乘加 |

## 唯一未穷尽的方向：提高并行度

**现状**：并行度上限为 `min(B, cores)`。**若某个测试点的 B 很小，多数核将空闲。**

**障碍**：按 (b, m 区间) 切分需要跨核归约，而：

- `AscendC::AtomicAdd` **仅支持 `__NPU_ARCH__` 5102/3510**，本项目是 2201 → 不可用
- `CrossCoreSetFlag`/`WaitFlag` 在 CPU 仿真下**行为不一致** → 无法本地验证
- 平台只调用一次 `run_kernel` → 无法用第二个 kernel 做最终归约

**该方向只能盲提交，且收益取决于平台实际核数与 B。**

## 结论

**标量路径的本地可验证优化已穷尽。** 上表 7 类尝试覆盖了：
分支、展开、批量搬运、裸指针、边界检查、循环重排、算法剪枝。

若要继续，只剩"提高并行度"（需盲提交）或"真机验证向量收益"两条路。
